# Features

Numbered register of every feature; a number is never reused. Every feature is covered by tests listed in [TESTS.md](TESTS.md); the guard `tests/docs-contract.sh` fails when a feature has no test.

- **F1 — Mount LizardFS.** The image carries the LizardFS client of Ubuntu 20.04; `lfsmount` mounts an existing LizardFS file system through FUSE, read and write, with the container started with `/dev/fuse` and `SYS_ADMIN`.
- **F2 — Copy data out.** `rsync` copies the data of the mounted LizardFS to another file system, such as a CephFS mounted into the container, for the migration away from LizardFS.
- **F3 — Published for amd64.** Every push builds the image and publishes it on Docker Hub, with the reusable workflow of `mwaeckerlin/scratch`. There is no arm64 image: the LizardFS master of Ubuntu 20.04 crashes on arm64, so an arm64 client cannot be tested against a LizardFS.
- **F4 — Configured mount.** The operator chooses at container start which LizardFS master is mounted, which folder of it becomes the root of `/mnt`, and which further mount options apply, without editing or mounting a file. Without a choice the image mounts as it always has: master `universum`, folder `/volumes`, options `mfsdelayedinit,nosuid,nodev,noatime,big_writes,mfschunkserverwriteto=40000,mfsioretries=120,mfschunkserverconnectreadto=20000,mfschunkserverwavereadto=5000,mfschunkservertotalreadto=20000`, always read and write. An empty option list mounts with master and folder alone. The same mount is available inside an interactive container as one command. A master that is no host name or IPv4 address, a folder that is no absolute path, or options with spaces stop the container before anything is mounted, with a message that names the setting and says what it accepts. The variable names stand in the README under Configuration.
- **F5 — Configured copy jobs.** The container started without a command mounts the LizardFS (F4) and then runs a list of rsync jobs the operator sets at start, one after the other; each job is the argument list of one rsync call. A job that fails does not stop the jobs after it, and the container exits with the status of the last job; when the mount fails, no job runs. Without a choice the image runs the five jobs it has always run, listed in the README; an empty list only mounts. A job argument with a character outside letters, digits and `_ . / = , : + @ % ~ * ? [ ] -` stops the container before anything is mounted, with a message that names the job.
